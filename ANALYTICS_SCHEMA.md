# GPT_EA Analytics Schema

This document is the versioned data contract for performance, execution, recovery, broker and risk analytics generated by GPT_EA. Do not silently change field meaning or units; incompatible changes require a new schema version.

## 1. Execution event log — `execution_events_v1`

Runtime file: `GPT_EA_Execution.csv` in the MT5 Common Files area.

| Field | Type | Unit / enum | Meaning |
|---|---|---|---|
| `time` | datetime string | trade-server time | Event timestamp |
| `event` | string | `ENTRY`, `EXIT_PART`, `CLOSED` | Lifecycle event |
| `symbol` | string | broker symbol | Actual resolved broker symbol |
| `setup` | string | `PULLBACK`, `BREAKOUT_RETEST` | Strategy family |
| `deal` | uint64 string | MT5 deal ticket | Deal that generated event |
| `position_id` | uint64 string | `POSITION_IDENTIFIER` | Durable position lifecycle identifier |
| `requested` | double | price | Planned/reference entry price |
| `actual` | double | price | Executed deal price |
| `slippage_pts` | double | symbol points | Absolute requested-vs-actual entry slippage |
| `R` | double | R multiple | Realized result divided by original planned monetary risk; final on `CLOSED` |
| `MAE_R` | double | R multiple | Maximum adverse excursion in units of initial risk |
| `MFE_R` | double | R multiple | Maximum favorable excursion in units of initial risk |
| `note` | string | free text | Event/recovery context |

### Event rules

**ENTRY** — one logical entry event per new position lifecycle. `R=0`; requested price comes from the pre-send plan; actual comes from the broker deal.

**EXIT_PART** — emitted for each exit deal, including partial exits. It is not by itself a finalized trade record.

**CLOSED** — emitted once per completed `position_id`; updates setup-level persistent statistics and sets the finalization guard.

## 2. Durable position key

`position_id` is the primary analytics/recovery key, not the current position ticket. Ticket-scoped fields are management helpers only.

All lifecycle orders/deals should be joined through the MT5 position identifier. This is especially important for partial fills, ticket changes and netting behavior.

## 3. Setup-performance aggregates — `setup_stats_v1`

Persistent terminal-global namespace:

`GPT<magic>_STAT_<setup_kind>_<metric>`

Setup kind:
- `1` = pullback
- `2` = breakout-retest

| Metric | Unit | Definition |
|---|---|---|
| `N` | trades | Finalized trade count |
| `WIN` | trades | Finalized trades with `R > 0` |
| `SUMR` | R | Sum of final R |
| `POSR` | R | Sum of positive final R |
| `NEGR` | R | Absolute sum of negative final R |
| `SLIP` | points | Sum of entry slippage points |
| `MAE` | R | Sum of MAE_R |
| `MFE` | R | Sum of MFE_R |

Derived metrics:
- Win rate = `WIN / N * 100`
- Average R / expectancy = `SUMR / N`
- Profit factor = `POSR / NEGR` when `NEGR > 0`
- Average slippage = `SLIP / N`
- Average MAE = `MAE / N`
- Average MFE = `MFE / N`

Pullback and breakout-retest aggregates must remain separate when evaluating setup edge.

## 4. Per-position state — `position_state_v1`

Terminal-global namespace:

`GPT<magic>_P<position_id>_<field>`

| Field | Unit / enum | Purpose |
|---|---|---|
| `KIND` | 1/2 | Pullback or breakout-retest |
| `ENTRY` | price | Lifecycle entry |
| `INITSL` | price | Original protective stop before BE movement |
| `RISK` | account currency | Original planned monetary risk |
| `REQUESTED` | price | Requested/reference entry |
| `SLIP` | points | Entry slippage |
| `OPEN_TIME` | server timestamp | Position open time |
| `MAE` | R | Running maximum adverse excursion |
| `MFE` | R | Running maximum favorable excursion |
| `REALIZED` | account currency | Accumulated realized P/L from exit deals |
| `FINAL` | 0/1 | Completed analytics already finalized |

`FINAL=1` is an idempotency guard: restart or duplicate transaction callbacks must not update setup statistics twice.

## 5. Ticket-scoped trade management — `trade_management_v1`

Namespace:

`CGPT_<position_ticket>_<field>`

| Field | Unit | Meaning |
|---|---|---|
| `INITSL` | price | Original stop |
| `TP1` | price | First target |
| `TP2` | price | Second target |
| `TP3` | price | Final target |
| `EXP` | M15 candles | Adaptive pre-TP1 expiry budget |
| `TP1DONE` | 0/1 | Partial/TP1 handling completed |

Because the ticket is not the durable identity, restart recovery reconciles this namespace against the current ticket for the same `POSITION_IDENTIFIER`.

## 6. Risk/session state — `risk_state_v1`

Terminal-global namespace: `GPT<magic>_<field>`.

| Field | Meaning |
|---|---|
| `DAYKEY` | server-date key `YYYYMMDD` |
| `DAYSTART_EQ` | equity at risk-day start |
| `EQUITY_PEAK` | persistent equity high-water mark |
| `PAUSED` | manual/recovery safety pause state |
| `CONSEC_LOSS` | consecutive finalized losing trades |

Per-symbol cooldown:

`GPT<magic>_<safe_symbol>_COOLDOWN`

Value: trade-server timestamp of most recent deny/timeout/completed-trade cooldown trigger.

## 7. Pending approval state — `pending_state_v1`

Per-symbol persisted fields include:

- active flag
- direction
- setup kind
- entry-zone low/high
- preferred entry
- SL / TP1 / TP2 / TP3
- confidence
- adaptive expiry
- approval expiration timestamp

Persistence is never authorization. Every recovered pending setup must pass a fresh scan, risk/broker gate and final validation before execution.

## 8. Recovery checkpoint — `recovery_state_v2`

Primary runtime file:

`GPT_EA_RecoveryState_<account_login>_<magic>.csv`

Validated backup:

`GPT_EA_RecoveryState_<account_login>_<magic>.csv.bak`

Location: MT5 Common Files area. Delimiter: semicolon.

### `META` row

`META;version;account_login;server;magic;snapshot_time`

Used for schema, account, server and magic-number isolation.

### `RISK` row

`RISK;day_key;day_start_equity;equity_peak;paused;consecutive_losses`

### `PENDING` row

`PENDING;symbol;bullish;setup_kind;zone_low;zone_high;preferred;sl;tp1;tp2;tp3;confidence;expiry_m15;created_at;expires_at`

Rules:
- expired offline approvals are never re-authorized;
- expired approvals enter normal cooldown handling;
- stored symbols are re-resolved against the current broker;
- duplicate in-memory state is not reconstructed twice.

### `POSITION` row

`POSITION;position_id;ticket;symbol;position_type;volume;entry;current_sl;current_tp;setup_kind;initial_sl;tp1;tp2;tp3;expiry_m15;tp1_done;risk_money;requested_price;slippage_pts;mae_r;mfe_r;final_flag`

Rules:
- open positions are found by `position_id`;
- stored ticket is audit metadata, not recovery primary key;
- a changed broker ticket receives reconstructed ticket-scoped management state;
- historical initial SL is preferred over current BE/moved SL when reconstructing original risk;
- exit-deal history can infer TP1 completion and prevent a second partial close.

### `END` row

`END;version;completed_at`

The `END` row marks a fully written checkpoint. A snapshot is eligible for promotion to `.bak` only when metadata matches the current account/server/magic and the completed END marker is present.

If the primary file is incomplete/corrupt at startup and a completed backup exists, GPT_EA restores the backup before disk recovery. Terminal globals, current positions and position history remain independent fallback/reconciliation sources.

## 9. Recovery precedence and safety

Recovery uses multiple sources deliberately:

1. current broker positions / position history — source of truth for what actually exists;
2. terminal Global Variables — fast persistent EA state;
3. completed primary/backup disk checkpoints — additional restart/crash resilience.

Important safety rules:
- never create a position merely because a checkpoint says one existed;
- reconcile only against a currently open GPT_EA position identifier;
- ignore account/server/magic mismatches according to configuration;
- fresh-scan recovered approvals before execution;
- pause on unrecoverable original-stop/setup-type inconsistency when configured;
- on netting accounts, compare original historical direction with current direction and pause if a reversal preserved the same identifier.

## 13. Units and normalization

- **Price:** broker price normalized to symbol tick size/digits.
- **Points:** price distance divided by `SYMBOL_POINT`.
- **Lots:** broker volume normalized to `SYMBOL_VOLUME_STEP`.
- **Money:** account currency unless explicitly documented otherwise.
- **R:** value divided by original planned monetary or price risk, according to field definition.
- **Time:** trade-server time unless field explicitly names UTC/local session time.
- **Percent:** human percentage (`1.0` = 1%) unless documented as a ratio.

## 14. Missing-data policy

- Do not fabricate broker properties, DOM, calendar events or yield data.
- Do not infer a historical initial SL from current breakeven when a better history source exists.
- Optional filters may fail open only when configuration explicitly permits it.
- Hard risk, broker execution and account-state failures fail closed.
- Unknown proprietary symbols should be supplied using the broker's actual MT5 symbol name rather than guessed.

## 15. Release/version rule

Archive together for each production release:

1. Git commit SHA;
2. compiled `.ex5` file/hash;
3. EA input preset;
4. `execution_events_v1` definition;
5. `recovery_state_v2` definition;
6. broker/symbol profile;
7. MetaTrader build number;
8. completed `COMPILE_TEST_CHECKLIST.md` result.

If a field is renamed, removed, changes unit, or changes semantic meaning, create a new schema version rather than silently modifying the existing contract.
