# GPT_EA Analytics Schema

This document is the data contract for performance, execution, recovery and risk analytics generated by GPT_EA.

Schema changes should be versioned. Do not silently change field meaning or units.

## 1. Execution event log — `execution_events_v1`

Runtime file: `GPT_EA_Execution.csv` in the MT5 Common Files area.

Current columns, in order:

| Field | Type | Unit / enum | Meaning |
|---|---|---|---|
| `time` | datetime string | server time | Event timestamp |
| `event` | string | `ENTRY`, `EXIT_PART`, `CLOSED` | Lifecycle event |
| `symbol` | string | broker symbol | Actual resolved broker symbol |
| `setup` | string | `PULLBACK`, `BREAKOUT_RETEST` | Strategy family |
| `deal` | uint64 string | MT5 deal ticket | Deal that generated event |
| `position_id` | uint64 string | `POSITION_IDENTIFIER` | Stable position lifecycle identifier |
| `requested` | double | price | Planned/reference entry price |
| `actual` | double | price | Executed deal price |
| `slippage_pts` | double | symbol points | Absolute requested-vs-actual entry slippage |
| `R` | double | R multiple | Realized result divided by original planned monetary risk; final on `CLOSED` |
| `MAE_R` | double | R multiple | Maximum adverse excursion in units of initial price risk |
| `MFE_R` | double | R multiple | Maximum favorable excursion in units of initial price risk |
| `note` | string | free text | Event/recovery context |

### Event rules

**ENTRY**
- one logical entry event per new position lifecycle;
- `R=0` at entry;
- requested price should come from the pre-send plan;
- actual price comes from the broker deal;
- slippage is measured in the symbol's own point size.

**EXIT_PART**
- emitted for each exit deal, including partial exits;
- not a completed-trade record by itself;
- used to reconstruct cashflow and audit TP1/management behavior.

**CLOSED**
- emitted once per completed `position_id`;
- `R` is final realized P/L including available commission and swap divided by original planned monetary risk;
- updates persistent setup-level statistics;
- marks the position final to prevent double counting after restart.

## 2. Position lifecycle key

`position_id` is the primary analytics key, not the current position ticket.

Reason: MT5's `POSITION_IDENTIFIER` is intended to link all orders/deals belonging to the same position lifecycle and remains the stable identifier used by `DEAL_POSITION_ID`/`ORDER_POSITION_ID`.

The current ticket may change during the lifecycle, so analytics and recovery must not use ticket as the durable primary key.

## 3. Setup-performance aggregates — `setup_stats_v1`

Persistent terminal-global namespace:

`GPT<magic>_STAT_<setup_kind>_<metric>`

Setup kind:
- `1` = pullback
- `2` = breakout-retest

Required metrics:

| Metric | Type | Unit | Definition |
|---|---|---|---|
| `N` | integer-like double | trades | Number of finalized trades |
| `WIN` | integer-like double | trades | Finalized trades with `R > 0` |
| `SUMR` | double | R | Sum of all final R results |
| `POSR` | double | R | Sum of positive final R |
| `NEGR` | double | R | Absolute sum of negative final R |
| `SLIP` | double | points | Sum of entry slippage points |
| `MAE` | double | R | Sum of MAE_R |
| `MFE` | double | R | Sum of MFE_R |

Derived fields:

- **Win rate** = `WIN / N * 100`
- **Average R / expectancy** = `SUMR / N`
- **Profit factor** = `POSR / NEGR` when `NEGR > 0`
- **Average slippage** = `SLIP / N`
- **Average MAE** = `MAE / N`
- **Average MFE** = `MFE / N`

Do not combine pullback and breakout-retest aggregates when evaluating setup edge.

## 4. Per-position persistent analytics — `position_state_v1`

Terminal-global namespace:

`GPT<magic>_P<position_id>_<field>`

Fields currently used or reserved:

| Field | Unit / enum | Purpose |
|---|---|---|
| `KIND` | 1/2 | Pullback or breakout-retest |
| `ENTRY` | price | Actual/reference lifecycle entry |
| `INITSL` | price | Original protective stop before BE movement |
| `RISK` | account currency | Original planned monetary risk |
| `REQUESTED` | price | Requested/reference entry |
| `SLIP` | points | Entry slippage |
| `OPEN_TIME` | server timestamp | Original position open time |
| `MAE` | R | Running maximum adverse excursion |
| `MFE` | R | Running maximum favorable excursion |
| `REALIZED` | account currency | Accumulated realized P/L from exit deals |
| `FINAL` | 0/1 | Completed analytics already finalized |

`FINAL=1` is an idempotency guard. A restart or duplicate trade transaction must not update the setup statistics twice.

## 5. Ticket-scoped management state — `trade_management_v1`

Legacy/current management namespace:

`CGPT_<position_ticket>_<field>`

Fields:

| Field | Unit | Meaning |
|---|---|---|
| `INITSL` | price | Original stop |
| `TP1` | price | First target |
| `TP2` | price | Second target |
| `TP3` | price | Final target |
| `EXP` | M15 candles | Adaptive pre-TP1 expiry budget |
| `TP1DONE` | 0/1 | Partial/TP1 handling completed |

Because the ticket is not the durable identity, restart recovery must reconcile these fields against `POSITION_IDENTIFIER` and current broker positions.

## 6. Risk/session state — `risk_state_v1`

Terminal-global namespace: `GPT<magic>_<field>`.

| Field | Meaning |
|---|---|
| `DAYKEY` | server-date key `YYYYMMDD` |
| `DAYSTART_EQ` | equity snapshot at current risk day start |
| `EQUITY_PEAK` | persistent equity high-water mark |
| `PAUSED` | manual pause state |
| `CONSEC_LOSS` | consecutive finalized losing trades |

Per-symbol cooldown namespace:

`GPT<magic>_<safe_symbol>_COOLDOWN`

Value: server timestamp of most recent deny/timeout/completed-trade cooldown trigger.

## 7. Pending approval state — `pending_state_v1`

Per-symbol terminal-global state stores enough information to reconstruct a pending approval:

- active flag
- direction
- setup kind
- entry zone low/high
- preferred entry
- SL
- TP1/TP2/TP3
- confidence
- adaptive expiry
- approval expiration timestamp

Recovery rule: persistence never equals authorization. Every recovered setup must pass a fresh market scan and final validation before execution.

## 8. Recovery checkpoint file — `recovery_state_v2`

Runtime file:

`GPT_EA_RecoveryState_<account_login>_<magic>.csv`

Location: MT5 Common Files area.

Delimiter: semicolon.

### `META` row

`META;version;account_login;server;magic;snapshot_time`

Purpose:
- version gate;
- account isolation;
- broker-server mismatch protection;
- snapshot audit timestamp.

### `RISK` row

`RISK;day_key;day_start_equity;equity_peak;paused;consecutive_losses`

### `PENDING` row

`PENDING;symbol;bullish;setup_kind;zone_low;zone_high;preferred;sl;tp1;tp2;tp3;confidence;expiry_m15;created_at;expires_at`

Rules:
- expired rows are never re-authorized;
- expired offline approvals trigger normal cooldown handling;
- symbol is re-resolved against the current broker before reconstruction;
- duplicate in-memory pending state wins over duplicate file reconstruction.

### `POSITION` row

`POSITION;position_id;ticket;symbol;position_type;volume;entry;current_sl;current_tp;setup_kind;initial_sl;tp1;tp2;tp3;expiry_m15;tp1_done;risk_money;requested_price;slippage_pts;mae_r;mfe_r;final_flag`

Rules:
- current open position is located by `position_id`;
- stored ticket is audit metadata, not the recovery primary key;
- if the broker ticket changed, ticket-scoped management state is rewritten for the current ticket;
- historical initial SL is preferred over a BE/moved current stop when reconstructing original risk;
- exit-deal history can infer TP1 completion and prevent a second partial close.

## 11. Units and normalization rules

- **Price:** raw broker price normalized to symbol tick size/digits.
- **Points:** divide price distance by `SYMBOL_POINT`.
- **Lots:** broker volume unit normalized to `SYMBOL_VOLUME_STEP`.
- **Money:** account currency unless explicitly documented otherwise.
- **R:** value divided by original planned monetary risk or original entry-to-initial-SL price risk, depending field definition.
- **Time:** trade-server time unless field explicitly says UTC/local session time.
- **Percent:** store human percentage (`1.0` = 1%), not fraction, unless field name/documentation says ratio.

## 12. Missing data policy

- Do not fabricate broker properties.
- Do not replace unavailable DOM with a fake neutral book.
- Do not fabricate economic events.
- Do not infer an unavailable historical initial SL from current BE unless no better source exists; mark the fallback in journal/recovery diagnostics.
- Optional filters may fail open only when their configuration explicitly permits it.
- Hard risk/broker execution failures fail closed.

## 13. Schema-version release rule

Archive these together for each production release:

1. Git commit SHA;
2. compiled `.ex5` hash/file;
3. EA input preset;
4. `execution_events_v1` definition;
5. `recovery_state_v2` definition;
6. broker/symbol profile;
7. MetaTrader build number;
8. test-checklist result.

If a field is renamed, removed, changes unit, or changes semantic meaning, create a new schema version rather than silently modifying the existing definition.
