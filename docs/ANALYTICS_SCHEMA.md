# GPT_EA Analytics Schema

This document is the versioned data contract for performance, execution, recovery, broker, risk and advanced position-management analytics generated by GPT_EA. Incompatible field/unit/semantic changes require a new schema version.

## 1. Execution event log — `execution_events_v1`

Runtime file: `GPT_EA_Execution.csv` in the MT5 Common Files area.

| Field | Type | Unit / enum | Meaning |
|---|---|---|---|
| `time` | datetime string | trade-server time | Event timestamp |
| `event` | string | lifecycle/stop event | Event type |
| `symbol` | string | broker symbol | Actual resolved broker symbol |
| `setup` | string | `PULLBACK`, `BREAKOUT_RETEST` | Strategy family |
| `deal` | uint64 string | MT5 deal ticket | Deal that generated event; zero for SL-management events |
| `position_id` | uint64 string | `POSITION_IDENTIFIER` | Durable lifecycle identifier |
| `requested` | double | price | Planned/reference entry; for stop events this remains entry reference |
| `actual` | double | price | Executed deal price or new protective-stop price for stop events |
| `slippage_pts` | double | symbol points | Entry slippage where applicable |
| `R` | double | R multiple | Final realized R on close or current position R at a stop-stage event |
| `MAE_R` | double | R multiple | Maximum adverse excursion |
| `MFE_R` | double | R multiple | Maximum favorable excursion |
| `note` | string | free text | Event/recovery/management context |

Supported lifecycle events:

- `ENTRY`
- `EXIT_PART`
- `CLOSED`

Supported protective-management events:

- `STOP_BREAKEVEN`
- `STOP_PROFIT_LOCK`
- `STOP_STRONG_LOCK`
- `STOP_TRAIL`

### Lifecycle rules

**ENTRY** — one logical entry event per new position lifecycle. `R=0`; requested price comes from the pre-send plan; actual comes from the broker deal.

**EXIT_PART** — emitted for each exit deal, including partial exits. It is not by itself a finalized trade record.

**CLOSED** — emitted once per completed `position_id`; updates setup-level persistent statistics and sets the finalization guard.

### Protective-stop event rules

Stop events are emitted only after a broker-accepted position modification. `actual` is the newly applied stop price and `R` is current unrealized movement in units of original initial risk. A failed, freeze-blocked or non-improving candidate does not create a successful stop-stage journal event.

## 2. Durable position key

`position_id` is the primary analytics/recovery key, not the current position ticket. Ticket-scoped fields are management helpers only. All lifecycle orders/deals should be joined through the MT5 position identifier.

## 3. Setup-performance aggregates — `setup_stats_v1`

Persistent terminal-global namespace:

`GPT<magic>_STAT_<setup_kind>_<metric>`

Setup kind:
- `1` = pullback
- `2` = breakout-retest

| Metric | Unit | Definition |
|---|---|---|
| `N` | trades | Finalized trade count |
| `WIN` | trades | Finalized trades with `R > 0` |
| `SUMR` | R | Sum of final R |
| `POSR` | R | Sum of positive final R |
| `NEGR` | R | Absolute sum of negative final R |
| `SLIP` | points | Sum of entry slippage points |
| `MAE` | R | Sum of MAE_R |
| `MFE` | R | Sum of MFE_R |

Derived metrics:
- Win rate = `WIN / N * 100`
- Average R / expectancy = `SUMR / N`
- Profit factor = `POSR / NEGR` when `NEGR > 0`
- Average slippage = `SLIP / N`
- Average MAE = `MAE / N`
- Average MFE = `MFE / N`

Pullback and breakout-retest aggregates remain separate.

## 4. Per-position durable state — `position_state_v2`

Terminal-global namespace:

`GPT<magic>_P<position_id>_<field>`

| Field | Unit / enum | Purpose |
|---|---|---|
| `KIND` | 1/2 | Pullback or breakout-retest |
| `ENTRY` | price | Lifecycle entry |
| `INITSL` | price | Original protective stop before BE movement |
| `RISK` | account currency | Original planned monetary risk |
| `REQUESTED` | price | Requested/reference entry |
| `SLIP` | points | Entry slippage |
| `OPEN_TIME` | server timestamp | Position open time |
| `MAE` | R | Running maximum adverse excursion |
| `MFE` | R | Running maximum favorable excursion |
| `REALIZED` | account currency | Accumulated realized P/L from exit deals |
| `FINAL` | 0/1 | Completed analytics already finalized |
| `SL_STAGE` | integer | 0 initial, 1 BE, 2 profit lock, 3 strong lock, 4 trailing |
| `LASTSL` | price | Last successfully persisted protective stop |
| `TP1PARTIAL` | 0/1 | TP1 reduction completed |
| `TP1DONE` | 0/1 | TP1 reduction/protection state completed |
| `TP1_TIME` | server timestamp | Time TP1 management first completed/was recorded |
| `TP2PARTIAL` | 0/1 | TP2 reduction completed |
| `TP2_TIME` | server timestamp | Time TP2 scale-out completed |

`FINAL=1` is an idempotency guard. TP1/TP2 flags are also idempotency guards: a restart/ticket change must not repeat a successful scale-out.

## 5. Ticket-scoped trade management — `trade_management_v2`

Namespace:

`CGPT_<position_ticket>_<field>`

Ticket-scoped fields mirror the current live management handle and may include:

| Field | Unit | Meaning |
|---|---|---|
| `INITSL` | price | Original stop |
| `TP1` | price | First target |
| `TP2` | price | Second target |
| `TP3` | price | Final target |
| `EXP` | M15 candles | Adaptive pre-TP1 expiry budget |
| `TP1PARTIAL` | 0/1 | TP1 reduction completed |
| `TP1DONE` | 0/1 | TP1 management complete |
| `TP1_TIME` | server timestamp | TP1 management timestamp |
| `TP2PARTIAL` | 0/1 | TP2 reduction completed |
| `TP2_TIME` | server timestamp | TP2 timestamp |
| `ADV_STAGE` | integer | Current reconstructed stop-management stage |

Durable `position_id` state takes precedence over a stale ticket-scoped flag. If the broker ticket changes, current-ticket fields are rebuilt/reconciled.

## 6. Protective-stop stage contract — `stop_management_v1`

Stages are monotonic in intended risk protection:

| Stage | Code | Default behavior |
|---|---:|---|
| Initial | 0 | Original SL |
| Breakeven | 1 | Cost-aware BE after TP1/`InpBETriggerR` |
| Profit lock | 2 | Default +0.5R after 1.5R |
| Strong lock | 3 | Default +1R after 2R |
| Trail | 4 | ATR + M5 structure trailing |

Rules:

- BUY stop never intentionally decreases.
- SELL stop never intentionally increases.
- all candidate stops normalize to broker tick size;
- current broker stop/freeze distance is checked before modify;
- trail-stage changes require the configured minimum R improvement;
- TP3 remains attached by default; runner mode may remove TP only when actual trailing begins;
- BE uses at least the greater of ATR cost buffer and current spread + modeled dynamic slippage cost.

## 7. Risk/session state — `risk_state_v1`

Terminal-global namespace: `GPT<magic>_<field>`.

| Field | Meaning |
|---|---|
| `DAYKEY` | server-date key `YYYYMMDD` |
| `DAYSTART_EQ` | equity at risk-day start |
| `EQUITY_PEAK` | persistent equity high-water mark |
| `PAUSED` | manual/recovery safety pause state |
| `CONSEC_LOSS` | consecutive finalized losing trades |

Per-symbol cooldown:

`GPT<magic>_<safe_symbol>_COOLDOWN`

## 8. Pending approval state — `pending_state_v1`

Persisted fields include active flag, direction, setup kind, entry zone, preferred entry, SL/TP1/TP2/TP3, confidence, adaptive expiry and approval expiration. Persistence is never authorization; every recovered approval is freshly rescanned.

## 9. Core recovery checkpoint — `recovery_state_v2`

Primary runtime file:

`GPT_EA_RecoveryState_<account_login>_<magic>.csv`

Validated backup:

`GPT_EA_RecoveryState_<account_login>_<magic>.csv.bak`

Location: MT5 Common Files; delimiter semicolon.

### `META`

`META;version;account_login;server;magic;snapshot_time`

### `RISK`

`RISK;day_key;day_start_equity;equity_peak;paused;consecutive_losses`

### `PENDING`

`PENDING;symbol;bullish;setup_kind;zone_low;zone_high;preferred;sl;tp1;tp2;tp3;confidence;expiry_m15;created_at;expires_at`

### `POSITION`

`POSITION;position_id;ticket;symbol;position_type;volume;entry;current_sl;current_tp;setup_kind;initial_sl;tp1;tp2;tp3;expiry_m15;tp1_done;risk_money;requested_price;slippage_pts;mae_r;mfe_r;final_flag`

### `END`

`END;version;completed_at`

Only a metadata-compatible snapshot with completed `END` marker is eligible for validated backup promotion.

Advanced management state is additionally reconstructed from durable position globals, current broker SL, position/deal history, and current ticket state. TP1/TP2 partial flags are written by `POSITION_IDENTIFIER` specifically so a ticket change does not by itself erase scale-out idempotency.

## 10. Recovery precedence and safety

1. current broker positions / deal history — source of truth for what exists and what executed;
2. `POSITION_IDENTIFIER`-scoped durable globals;
3. current-ticket management globals;
4. completed primary/backup checkpoint.

Important rules:
- never create a position because persistence says one existed;
- reconcile only against a current open GPT_EA identifier;
- ignore account/server/magic mismatches according to policy;
- fresh-scan recovered approvals;
- pause on unrecoverable original-stop/setup-type inconsistency when configured;
- detect netting direction reversal;
- infer/reconcile scale-out state from broker history where possible rather than repeating an exit blindly.

## 11. Broker/symbol profile — `broker_profile_v1`

Recommended release fields include broker company/server, account currency/leverage/margin mode, symbol/canonical/asset class, description/path, base/profit/margin currency, digits/point/tick size, tick values, contract size, volume rules, spread, stop/freeze levels, trade/calc/filling modes and buy/sell margin estimates.

## 12. Order preflight observation — `order_preflight_v1`

Recommended fields:
- symbol/direction/setup kind
- requested volume
- Bid/Ask spread
- dynamic slippage ceiling
- normalized SL/TP
- trade/execution/filling modes
- `OrderCalcMargin` result
- pre-trade free margin
- margin-use cap
- `OrderCheck` retcode/comment
- projected balance/equity/margin/free margin/margin level
- allow/block result/reason

## 13. Signal/setup observation — recommended `setup_observation_v1`

Future scan export should include identity/time, broker symbol/canonical instrument, setup/direction, all D1-H4-H1-M30-M15-M5 votes, confluence, ADX/DI, RSI, ATR, opening-range ratio, spread, VWAP/volume, level-quality, sweep/FVG/SDR, regime, DOM/ONNX when present, planned price/risk/margin fields, all hard gate results, and final outcome fields populated only after completion.

Outcome fields must never be model inputs for the same observation.

## 14. Units and normalization

- **Price:** broker price normalized to symbol tick size/digits.
- **Points:** price distance / `SYMBOL_POINT`.
- **Lots:** broker volume normalized to `SYMBOL_VOLUME_STEP`.
- **Money:** account currency unless documented otherwise.
- **R:** divided by original initial planned risk according to field definition.
- **Time:** trade-server time unless explicitly named otherwise.
- **Percent:** human percentage (`1.0` = 1%) unless documented as ratio.

## 15. Missing-data policy

- Do not fabricate broker properties, DOM, calendar events or yield data.
- Prefer historical original SL over current BE for original-risk reconstruction.
- Optional filters fail open only when configuration explicitly permits.
- Hard risk, release, broker and account-state failures fail closed.
- Unknown proprietary symbols use the actual broker MT5 name rather than guessed aliases.

3. EA `.set` input preset;

7. completed `COMPILE_TEST_CHECKLIST.md`;

9. at least one validated TP1 → BE → profit-lock → trail lifecycle.
